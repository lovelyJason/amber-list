# 琥珀清单 - 多云端同步架构设计

> 最后更新：2026-01-02

---

## 1. 概述

琥珀清单支持多种云端同步方式，采用 **Go 风格的面向接口编程**，实现了统一的同步抽象层。

### 1.1 支持的同步方式

| 同步类型 | 状态 | 说明 |
|---------|------|------|
| WebDAV | ✅ 已实现 | 坚果云等 WebDAV 服务 |
| 七牛云 OSS | ✅ 已实现 | 七牛云对象存储（自托管模式） |
| 阿里云 OSS | 🔜 预留 | 阿里云对象存储 |
| 腾讯云 COS | 🔜 预留 | 腾讯云对象存储 |
| 琥珀云 | 🔜 预留 | 官方托管服务 |

### 1.2 多配置单激活

**设计理念**：用户可以同时配置多个平台的账密信息，但同一时间只能激活一个同步方式。

- **配置独立保存**：WebDAV 和七牛云的配置各自独立存储，互不影响
- **单选激活**：通过 Radio 按钮选择当前激活哪个同步方式
- **无需删除**：切换同步方式时，不会删除其他平台的配置，随时可以切回
- **支持关闭**：可以选择"不同步"完全关闭云同步功能

### 2.2 核心接口

```dart
/// 同步存储提供者接口

abstract class ISyncStorageProvider {
  SyncStorageType get type;

  Future<SyncResult<void>> testConnection();
  Future<SyncResult<void>> ensureAppDirectory();
  Future<SyncResult<void>> uploadDatabase(String localPath);
  Future<SyncResult<bool>> downloadDatabase(String localPath);
  Future<SyncResult<Map<String, dynamic>?>> readMetadata();
  Future<SyncResult<void>> writeMetadata(Map<String, dynamic> data);
  Future<SyncResult<bool>> acquireLock({...});
  Future<SyncResult<void>> releaseLock(String deviceId);
  Future<SyncResult<void>> uploadSnapshot(String localPath, String name);
  Future<SyncResult<void>> cleanOldSnapshots({int keepCount = 10});
  void dispose();
}
```

```dart

  Future<SyncResult<void>> deleteFile(String remoteKey);
  Future<SyncResult<List<String>>> listFiles(String prefix);
```

## 3. 七牛云 OSS 实现细节

### 3.1 为什么在客户端生成 Token？

七牛官方文档说"客户端 SDK 不含 token 生成"，这是针对 **Web/移动端** 的安全建议——因为 Web 端的 JavaScript 代码容易被反编译，SecretKey 会暴露。

但琥珀清单是 **桌面应用**，情况完全不同：

| 场景 | SecretKey 安全性 | 建议 |
|------|-----------------|------|
| Web 应用 | ❌ 危险（JS 可被反编译） | 必须服务端生成 Token |
| 移动 App（发布版） | ⚠️ 有风险（APK 可被逆向） | 建议服务端生成 |
| **桌面应用（自托管）** | ✅ 安全 | 客户端生成 OK |

**原因**：
1. 用户自己输入 AK/SK，存储在系统 Keychain（macOS）或 Credential Manager（Windows）
2. 除非用户自己泄露，否则没人知道密钥
3. 类似 OSS Browser、Cyberduck 等官方/知名客户端都是这么做的

### 3.2 Token 生成实现

我们在 `QiniuOssClient` 中实现了完整的 Token 生成逻辑：

```dart
/// 生成上传 Token（覆盖上传策略）
String _generateUploadToken(String? key) {
  final deadline = DateTime.now().add(const Duration(hours: 1)).millisecondsSinceEpoch ~/ 1000;
  final putPolicy = {
    'scope': key != null ? '$bucket:$key' : bucket,
    'deadline': deadline,
    'insertOnly': 0, // 允许覆盖
  };

  final encodedPolicy = _urlSafeBase64Encode(utf8.encode(jsonEncode(putPolicy)));
  final sign = _hmacSha1Sign(encodedPolicy);
  return '$accessKey:${_urlSafeBase64Encode(sign)}:$encodedPolicy';
}

/// 生成私有下载 URL（带签名）
String _generatePrivateDownloadUrl(String key) {
  final domain = customDomain ?? 'http://$bucket${region.downloadHostSuffix}';
  final deadline = DateTime.now().add(const Duration(hours: 1)).millisecondsSinceEpoch ~/ 1000;
  final urlWithDeadline = '$domain/$key?e=$deadline';

  final sign = _hmacSha1Sign(urlWithDeadline);
  return '$urlWithDeadline&token=$accessKey:${_urlSafeBase64Encode(sign)}';
}

/// 生成管理凭证（RS API 鉴权）
String _generateManagementToken(String path, String? body) {
  final signingStr = '$path\n${body ?? ''}';
  final sign = _hmacSha1Sign(signingStr);
  return '$accessKey:${_urlSafeBase64Encode(sign)}';
}
```

### 3.3 API 调用方式

| 操作 | API | 认证方式 |
|-----|-----|---------|
| 上传文件 | `qiniu_flutter_sdk` | Upload Token |
| 下载文件 | HTTP GET + 签名 URL | 私有链接签名 |
| 检查文件 | RS API `/stat` | QBox Token |
| 删除文件 | RS API `/delete` | QBox Token |
| 列出文件 | RSF API `/list` | QBox Token |

## 5. 数据同步流程

### 5.1 同步目录结构

无论是 WebDAV 还是 OSS，远程数据结构保持一致：

```
{root}/AmberList/
├── amber_list.db           # 主数据库文件
├── sync_metadata.json      # 同步元数据（版本、校验和）
├── .sync.lock              # 同步锁（防止并发）
└── snapshots/              # 历史快照
    ├── amber_list_1704067200000.db
    └── amber_list_1704153600000.db
```

### 5.2 三向合并

当本地和远程都有修改时，执行三向合并：

```
       Base (上次同步点)
          /       \
         /         \
      Local       Remote
         \         /
          \       /
           Merged
```

合并策略：
- 任务：按 `updated_at` 时间戳取较新版本
- 标签：名称冲突时保留两者，标记冲突供用户解决
- 列表：合并不冲突的修改

### 6.2 托管模式（琥珀云）

托管模式与自托管模式的区别：

| 特性 | 自托管模式 | 托管模式 |
|-----|-----------|---------|
| 密钥管理 | 用户自己的 AK/SK | 服务端授权 |
| Token 生成 | 客户端 | 服务端 |
| 认证方式 | 直接鉴权 | 激活码/账号 |
| 存储费用 | 用户承担 | 包含在订阅中 |

托管模式的实现需要：
1. 后端 API 签发临时访问凭证
2. 客户端使用临时凭证访问 OSS
3. 定期刷新凭证
