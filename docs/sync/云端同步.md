 整个 DB 文件同步的核心挑战

  当你用整个 amber_list.db 文件同步时，会遇到这几种场景：

  场景分析

  | 场景   | 本地状态 | 远程状态     | 怎么处理？             |
  |--------|----------|--------------|------------------------|
  | 场景 A | 本地没改 | 远程有更新   | 简单，直接下载覆盖本地 |
  | 场景 B | 本地有改 | 远程没更新   | 简单，直接上传覆盖远程 |
  | 场景 C | 本地有改 | 远程也有更新 | 这是核心难题！         |

  场景 C 详解：
  - 你在 Mac 上改了任务 A 的标题
  - 你同事/另一台设备在 Windows 上改了任务 B 的描述
  - 两边都有修改，但修改的是不同记录
  - 如果直接用"后提交覆盖先提交"，会丢失一边的修改！

  ---
  解决方案：DB 文件同步 + 三向合并

  卧槽，这才是正解！不用每条记录一个文件，但需要在同步时临时打开两个 DB 做合并：

  核心思路

  ┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
  │  本地 DB        │     │  远程 DB        │     │  上次同步快照    │
  │  (当前版本)     │     │  (从 WebDAV 下载) │     │  (存在本地)     │
  └────────┬────────┘     └────────┬────────┘     └────────┬────────┘
           │                       │                       │
           └───────────────────────┼───────────────────────┘
                                   │
                                   ▼
                       ┌───────────────────────┐
                       │  三向合并算法          │
                       │  (逐表逐记录比较)      │
                       └───────────┬───────────┘
                                   │
                                   ▼
                       ┌───────────────────────┐
                       │  合并后的 DB           │
                       │  (上传到 WebDAV)       │
                       └───────────────────────┘

  三向合并算法

  /// 三向合并核心算法
  Future<void> threeWayMerge({
    required AppDatabase localDb,      // 本地数据库
    required AppDatabase remoteDb,     // 从 WebDAV 下载的远程数据库
    required AppDatabase baseDb,       // 上次同步快照（基准）
  }) async {
    // 遍历每张表
    for (final table in ['tasks', 'task_lists', 'notes', 'tags']) {
      final localRecords = await localDb.getAll(table);
      final remoteRecords = await remoteDb.getAll(table);
      final baseRecords = await baseDb.getAll(table);

      // 建立索引 Map
      final localMap = {for (var r in localRecords) r.id: r};
      final remoteMap = {for (var r in remoteRecords) r.id: r};
      final baseMap = {for (var r in baseRecords) r.id: r};

      final allIds = {...localMap.keys, ...remoteMap.keys, ...baseMap.keys};

      for (final id in allIds) {
        final local = localMap[id];
        final remote = remoteMap[id];
        final base = baseMap[id];

        // === 情况 1：只有本地有（新增） ===
        if (local != null && remote == null && base == null) {
          // 本地新增，保留
          continue;
        }

        // === 情况 2：只有远程有（远程新增） ===
        if (remote != null && local == null && base == null) {
          // 远程新增，插入本地
          await localDb.insert(table, remote);
          continue;
        }

        // === 情况 3：两边都有，需要比较 ===
        if (local != null && remote != null) {
          final localChanged = base == null || local.updatedAt != base.updatedAt;
          final remoteChanged = base == null || remote.updatedAt != base.updatedAt;

          if (!localChanged && remoteChanged) {
            // 本地没改，远程改了 → 用远程
            await localDb.update(table, remote);
          } else if (localChanged && !remoteChanged) {
            // 本地改了，远程没改 → 保持本地（上传时会覆盖远程）
            continue;
          } else if (localChanged && remoteChanged) {
            // 两边都改了 → 智能合并！
            final merged = await smartMerge(local, remote, base);
            await localDb.update(table, merged);
          }
        }

        // === 情况 4：本地删除 / 远程删除 ===
        // ... 类似逻辑
      }
    }
  }

  智能合并（字段级别）

  /// 字段级智能合并
  Future<Task> smartMerge(Task local, Task remote, Task? base) async {
    // 逐字段比较
    return Task(
      id: local.id,

      // 标题：谁改了用谁的，都改了用最新的
      title: _mergeField(local.title, remote.title, base?.title, local.updatedAt, remote.updatedAt),

      // 描述：同上
      description: _mergeField(local.description, remote.description, base?.description, local.updatedAt, remote.updatedAt),

      // 完成状态：优先已完成（任何一边完成就算完成）
      isCompleted: local.isCompleted || remote.isCompleted,

      // 截止日期：用最新修改的那边
      dueDate: local.updatedAt.isAfter(remote.updatedAt) ? local.dueDate : remote.dueDate,

      // 时间戳：取最新
      updatedAt: local.updatedAt.isAfter(remote.updatedAt) ? local.updatedAt : remote.updatedAt,

      // 其他字段...
    );
  }

  T _mergeField<T>(T local, T remote, T? base, DateTime localTime, DateTime remoteTime) {
    if (local == remote) return local;  // 没冲突
    if (local == base) return remote;   // 本地没改，用远程
    if (remote == base) return local;   // 远程没改，用本地
    // 都改了，用最新的
    return localTime.isAfter(remoteTime) ? local : remote;
  }

  文件存储方案

  WebDAV 服务器/AmberList/
  ├── amber_list.db              # 最新的完整数据库
  ├── amber_list_meta.json       # 元数据（版本号、最后修改时间、设备ID）
  └── snapshots/                 # 历史快照（可选，用于回滚）
      └── amber_list_20251228.db

  本地存储：
  ~/Library/Containers/.../Documents/
  ├── amber_list.db              # 当前数据库
  ├── amber_list_sync_base.db    # 上次同步快照（用于三向合并）
  └── sync_config.json           # 同步配置

  完整同步流程

  用户点击"同步"按钮
         │
         ▼
  ┌──────────────────────────────────────────┐
  │ 1. 下载远程 DB 文件                        │
  │    GET /AmberList/amber_list.db           │
  │    保存为 temp_remote.db                  │
  └──────────────────────────────────────────┘
         │
         ▼
  ┌──────────────────────────────────────────┐
  │ 2. 下载远程元数据                          │
  │    GET /AmberList/amber_list_meta.json    │
  │    检查远程版本 vs 本地版本                │
  └──────────────────────────────────────────┘
         │
         ├─── 远程没更新 & 本地没改 → 结束（无需同步）
         │
         ├─── 远程没更新 & 本地有改 → 直接上传本地 DB
         │
         ├─── 远程有更新 & 本地没改 → 直接下载覆盖本地
         │
         └─── 远程有更新 & 本地有改 → 三向合并
                │
                ▼
  ┌──────────────────────────────────────────┐
  │ 3. 三向合并                               │
  │    打开 local.db、remote.db、base.db      │
  │    逐表逐记录比较、智能合并                │
  │    结果写入 local.db                      │
  └──────────────────────────────────────────┘
         │
         ▼
  ┌──────────────────────────────────────────┐
  │ 4. 上传合并后的 DB                        │
  │    PUT /AmberList/amber_list.db           │
  │    PUT /AmberList/amber_list_meta.json    │
  └──────────────────────────────────────────┘
         │
         ▼
  ┌──────────────────────────────────────────┐
  │ 5. 更新本地同步快照                        │
  │    复制 local.db → sync_base.db           │
  └──────────────────────────────────────────┘
         │
         ▼
       完成！
